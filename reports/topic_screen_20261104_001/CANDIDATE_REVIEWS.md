# 两个低比特通信问题的详细审查卡

日期：2026-11-04。两个对象均为“有真实问题依据、当前不建议立项”。以下最小验证只描述将来有具体方法时需要什么证据，不是已启动或安排执行的实验。

## 审查卡一 整数聚合的溢出风险与累加位宽

### 具体问题及已有证据

固定源量化精度 q、公共尺度、归约拓扑和实际码流，能否以较少的累加位宽 b，控制整条聚合路径任一中间和的溢出及饱和误差？这关注整数动态范围，不等于此前逐跳重数量化的 RS/AG 精度配置问题。

[THC](https://www.usenix.org/system/files/nsdi24-li-minghao.pdf) §8.4 最后部分和附录 D 明确讨论：worker 增多时，最大聚合范围增大，固定下行位宽需降低粒度，固定粒度则需增加位数。[HotNets 2024](https://arxiv.org/html/2407.01378v2) §3.2.2 提出饱和聚合，并承认更多 worker 等设置可能需要 b>q；其实验结果不能外推为任意输入都不溢出。

[Global-QSGD](https://mcanini.github.io/papers/gqsgd.ecai25.pdf) §4.2、§8 也直接处理低位宽与保护位的矛盾，并研究指数编码或逐步平均。不能根据标题中的“Quantize Once”就认为所有配置都不存在归约中的舍入误差。

### 考虑过的改法及未成立的区别

考虑以少量输入统计或历史统计选择 b，使整条路径的溢出概率或最终失真不超过目标。这个表述尚不是一个完整算法。直接增加保护位、对独立模型套用尾界、按历史范围设置尺度，都有成熟依据；[IntSGD](https://arxiv.org/pdf/2102.08374) §4 已有历史信息和 safeguard 的尺度设计。

真正缺少的是：可获得的统计量、具体决策规则，以及为什么在包括统计通信和计算的完整预算下优于简单固定或离线校准策略。本轮没有补出这一差异。

尤其需要避免四个错误：

1. 共同正交旋转保持 worker 向量间的内积，不能把它解释为不同 worker 自动独立或必然抵消。
2. 最终和不超范围，不能保证中间和安全。饱和加法通常不满足结合律，后来的抵消也不会恢复已经截断的信息。
3. 仅知道每个 worker 的范数，不能区分同向和相互抵消的输入；使用当前跨 worker 统计或 sketch，需要记录其成本。
4. 分布假设下的概率界与任意固定梯度的保证不同。只构造一个同向反例或套用 union bound，不足以形成新的研究结果。

尺度协调也不是未被考虑的开销：THC §5.3 和 [SwitchML](https://www.usenix.org/system/files/nsdi21-sapio.pdf) §3.3 已分别讨论统计交换及 look-ahead/piggyback 的处理。把这些步骤隐藏在“共享尺度已知”里会产生不公平比较。

### 必要强基线

| 基线 | 用途 |
|---|---|
| 宽整数精确和及满足最坏情况的安全位宽 | 数值参照和安全通信成本 |
| 固定饱和方案、少量固定保护位 | 防止新规则只胜过故意不足的累加范围 |
| 简单离线校准选位宽或尺度 | 判断复杂预测是否提供额外信息 |
| 同预算的线性和指数聚合方案 | 比较不同表示对动态范围的处理；保证类型需分别说明 |

统计、元数据、padding、实际打包及所有发送必须计入字节；不能用名义 q 替代实际载荷。当前 G1 的 LUT 索引不是可直接相加的线性整数编码，需要新的协议定义与参照，不自动复用其正确性结论。

### 单卡能提供的最小证据

若将来提出具体规则，先用独立整数参照核验路由、舍入和饱和；覆盖同向、抵消但前缀较大、幅度不均和实际梯度输入。记录所有中间溢出事件、偏差、MSE、实际字节及全部统计开销。用未参与规则开发的输入比较上述基线，冻结决策时实际可用的信息。

这些证据可支持误差与字节主张，不能独立支持真实 AllReduce 吞吐或训练加速。正文若要讨论训练质量，还需相应闭环证据，不能由低 MSE 自动推断。

### 判定与停止条件

**当前不立项。** 若方法仅是标准保护位、尾界或校准阈值；需要先知道当前全局和才能作出“事前”决策；计入协调后不再节省；或价值只能靠假定链路速度展示，则不进入实验。

重新审查需要一份具体方法说明，至少给出超出上述方案的一个可检查改进，例如在明确输入域内用更少可获得信息实现非保守的风险控制。它不需要宣称首次，但必须说清相对已有方案实际改变了什么。

## 审查卡二 是否对梯度块执行旋转

### 具体问题及已有证据

随机旋转可改善某些量化器的输入分布，但也消耗计算和访存。对固定发送字节和误差目标，能否提前判断某个梯度块是否值得旋转，并让判断成本低于省下的开销？

[Flash Communication v2](https://arxiv.org/html/2412.04964v2) §5.2、Table 5 在其推理通信设置中报告：旋转收益与量化粒度和格式有关。这是动机证据，不是已经观察到同样规律在本项目所有梯度上成立。

已有直接方案包括：HotNets 2024 §3.2.2 的 partial rotation；[HAGC](https://cs.newpaltz.edu/~lik/publications/Aiqiang-Yang-JSA-2026.pdf) §3 的硬件适配块变换和动态尺度；[RHT 分析 v2](https://arxiv.org/html/2605.06014v2) §7 的输入矩检查。最后一项选择 1/2/3 次变换，不能等同于已经解决 0/1 旋转选择，但必须作为相邻强基线。

### 考虑过的改法及未成立的区别

考虑使用最大值、能量或高阶矩，在原空间细粒度量化和旋转后量化之间选择。当前没有得到优于已有矩检查、校准查表或直接压缩误差估计的新判据。若先完整计算两种路径再择优，就要支付双路径成本，不能只计被选中方法的时间。

聚合兼容性也需要额外解决。对压缩域直接聚合，各 worker 的变换和解释方式必须兼容；独立选择不同 mask/变换可能破坏该条件。若先解码再聚合，可以支持不同表示，但算术、开销和方法定位随之改变。共享决策中的标志、统计同步或格式描述不能视为免费。

### 必要强基线

| 基线 | 用途 |
|---|---|
| 细粒度原空间量化 | 防止为一个过粗量化配置补救后误判收益 |
| 固定完整 RHT 与 partial rotation | 比较旋转收益及分块减少成本的直接方案 |
| 输入矩决定 RHT 次数的已有方法 | 比较相邻的自适应选择能力，明确 0/1 与 1/2/3 的区别 |
| 仅开发数据校准后固定的规则 | 检验复杂预测器是否优于简单选择 |

离线双路径择优只能作为 oracle，不能伪装为免费可执行基线。所有方法都应在相同实际字节和明确码流下比较，统计选择成本、预处理、元数据及解码。

### 单卡能提供的最小证据

若以后有明确新判据，冻结训练外的开发与留出梯度，分别测失真、选择错误造成的损失、完整局部耗时和显存。通过 CPU 参照检验不同选择下的聚合语义。旧三个快照仍是开发数据，不能充当独立泛化测试。

单卡可以验证“更便宜的局部量化选择是否达到同等误差”，不能凭该结果宣称多卡通信或大模型训练更快。若核心主张依赖实际通信重叠，则需要另有系统证据，超出当前小题边界。

### 判定与停止条件

**当前不立项。** 若选择器只是现有输入矩阈值、校准表或事后双路径挑优；只胜过全旋转和粗量化两个弱对照；需要忽略协调成本才能获益；或没有维护一致的聚合语义，则停止。

本轮没有找到可负责任地称为“待验证新方法”的判据，因此不先建立一个大实验网格来寻找有利条件。
