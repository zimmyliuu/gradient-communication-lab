# 低比特梯度通信下一轮诊断任务

版本：1.0。日期：2026-11-04。执行对象：用户或后续实施助手。环境：现有单张 RTX 4000 Ada。当前交付是任务安排，实验尚未启动。

**本轮只回答一个问题：在一个官方成熟量化组件上，能否找到真实梯度中可复现、值得改进的具体问题，从而为独立贡献提供依据？** 不要求先发明新算法，也不把完成比较实验本身当成独立贡献。评价先看问题和证据，不以目标期刊或页数决定结论。

执行范围为 D0 官方基线资格核验、D1 开发集比较，以及有线索时的少量定位。结束后提交报告，由下一轮复核决定是否进行 D2 独立确认。完整训练、新数据采集和新算法实现不在本次默认任务内。

配套文件：[交付要求](DELIVERY_FORMAT.md)、[报告模板](REPORT_TEMPLATE.md)、[摘要模板](summary.template.json)。本安排优先于旧技术方案中的下一步建议；已验收结果和已停止候选的历史结论不改写。

## 1 成果目标和投入边界

合格交付可以是以下任一结果：

- 官方组件难以在当前环境可靠调用，明确阻碍及已尝试范围，停止本轮。
- 比较有效，但差异属于预期的位宽、尺度粒度或成本取舍，没有找到可推进线索，停止扩展。
- 找到一条通过复查的问题线索，说明具体触发条件、影响大小、涉及步骤和下一次最小确认方案。此时仍不能写成独立贡献已经成立。

本轮最多接入一个外部方法族，优先 DynamiQ 的官方固定配置 codec 组件。块均匀量化是简单参照，BF16 是输入精度参照；不再扩展多个外部框架。已有 G1/G2a 用于复用输入、打包检查、账本和报告工具，不重跑其完整验收矩阵。

投入上限是停止规则，不是必须耗尽的额度：

| 工作 | 上限 | 超限处理 |
|---|---|---|
| D0 下载、读接口、构建及兼容性排障 | 主动工作 4 小时；最多两轮有明确原因的构建修复 | 保存日志，提交 baseline_blocked，不继续移植 |
| D1 比较适配与诊断 | 主动工作 1 个工作日；新增 GPU 执行累计 2 小时 | 保存已完成部分，提交 incomplete，不自动扩矩阵 |
| 线索定位 | 最多一条线索、两项单因素对照，计入 D1 额度 | 仍有歧义则写 inconclusive |
| 本轮新训练、完整系统移植、多卡测量 | 0 | 留给后续独立任务 |

不新增高性能 uniform CUDA 内核，不恢复 G2b–G4，不恢复随机耦合或两轮精确矩候选。环境安装如有必要，只能在当前项目内使用隔离环境；不升级现有共享 PyTorch、驱动或封存实验环境。不要为本轮新建 Linux/WSL 或多机部署工程。

## 2 D0 官方基线资格核验

### 2.1 先确定实际调用的是哪份代码

已有来源清单为 [dynamiq_source.json](../../../spl_model_communication/provenance/dynamiq_source.json)，冻结 commit 是 96da2ee480bbfd8e2049de3fbd8595cc9d7a30b8。本地 provenance/upstream/dynamiq 目前保存的是部分模拟代码、说明和元数据，不能据此认为官方 CUDA 组件已经齐备、可构建或通过验证。

从[官方仓库](https://github.com/CharlesHan24/DynamiQ)取得该固定版本所需组件，在新目录保存来源、许可证、文件哈希和构建日志。先检查上游说明及相关修复记录：如果冻结版本有已经明确修复、会影响比较的缺陷，应在 D1 之前确定版本处理办法并记录，不把已修复的旧问题包装成发现。不要无记录地切换到 latest。

基线名称使用 official_dynamiq_fixed_codec，附 commit、入口、实际配置和构建身份；它表示官方固定组件，不表示完整 DynamiQ 训练或通信系统。优先选与既有名义 b4/b8 相应、官方接口实际支持的两档配置，低精度为主，高精度为对照；若官方参数含义不同，按官方定义记录，不能硬套本地标签。

现有 index_repaired_bf16 和 source_kernel_bf16 均不自动具备官方 CUDA 基线资格。不能把任一名称改成 official，或通过在本地重新实现近似公式绕过 D0。

### 2.2 准入条件

运行 D1 前，baseline_qualification.json 必须明确回答：

1. 能否通过官方局部接口，在单 GPU 上完成实际编码和解码？需要哪些外部状态、预处理和共享信息？
2. 输入和输出 dtype、码值范围、主码宽度、尺度格式、padding、溢出行为是什么？哪些操作使用 FP32/BF16？
3. 实际包是什么？解码能否只靠包及事先声明的静态状态完成，而不读取未记账的原输入、逐块最大值等辅助信息？
4. 能否按官方合法接口改变随机种子或状态，产生重复实验？局部随机边缘分布与跨 worker 的状态关系是什么？
5. 是否通过相关官方自测及本轮小型输入检查？是否存在与参考实现不一致的情况？

允许修改路径、构建参数和隔离局部接口所必需的胶水；保留逐项 diff。改变尺度规则、随机舍入、主码索引、融合算术或解码精度，均视为改变算法语义，不能继续标为原官方基线。

最小检查覆盖：全零、常数与正负混合、一个稀疏大值输入、一个随机输入、一个真实输入，以及官方最小合法长度和一个需要尾部处理的长度。验证输入保护、包可独立解码、实际存储字节、同一合法随机状态下的可重复性。按官方契约处理极值和非法输入，不以改变 dtype 或放宽误差容差掩盖失败。每一失败保留最小可复现输入。

**D0 通过要求官方局部算术可实际运行且身份清楚，不要求完整分布式框架可运行。** 如只能运行本地适配器、需要重写核心 CUDA、必须启动多机/NCCL，或无法确定包的独立解码语义，则停止并交付阻碍报告。官方模拟脚本可以帮助查因，但不能悄悄替代本轮选择的官方 CUDA 组件。报告注明这是实现可达性问题，不是科学上的负结果。

## 3 D1 输入和随机重复

### 3.1 只使用已有开发输入

数据以[完整 G1 输入清单](../../results/gpu_codec_v1/gpu_codec_v1_20261104_001/input_manifest.json)为入口，使用 training_seed=1101、update=100/500/2500 的三个快照，每个快照四个 worker，逻辑长度 D=818048。核对清单、实际张量和文件哈希。

这些夹具的变换是原始 FP32 梯度 → BF16 → 在 BF16 中除以 4 → 末尾补零。读取逻辑部分，**不得再次除以 4，也不得把旧 padding 当成新输入**。各方法根据自己的合法长度单独补齐；保存逻辑长度和实际补齐长度，误差统计只覆盖逻辑部分。

所有方法使用同一组预除后的 BF16 输入 x_r。它们来自一个小型 Transformer 的一条训练轨迹，是开发数据，不代表大模型总体。3 个快照、12 个 worker 张量和随机重复数分别报告；不能相乘后当成独立训练样本数。

本轮不读取以前划定的正式留出数据，不把未在本轮查看的旧开发快照重新命名为留出集，不新增训练或下载模型。逐层统计若需要，可从已有参数映射派生，但不能借此重新选择只对某方法有利的输入切片。

### 3.2 固定随机规则

每个随机配置使用 8 个重复，repeat_id=0..7；确定性参照只执行一次。固定输入、worker、方法配置和重复到种子/状态的映射，记录完整规则和状态哈希。采用新的 bounded_discovery_v1 命名空间，与旧夹具阈值分开。

官方方法保留其合法局部随机生成方式。one-shot 求和诊断要求各 worker 的局部随机流彼此独立，优先通过官方种子/状态接口设置；不改写官方 RNG 来凑共同阈值。若无法通过合法接口满足并核验这一条件，可继续局部误差比较，但跨方法聚合比较标为不具备可比条件，不据此判断相关噪声优劣。

跨方法使用同一个整数 seed 不等于使用相同随机变量。结果按输入配对，随机重复用于观察每份输入上的离散程度，不作跨方法共同随机数配对，不声称 8 次重复已经证明无偏性或统计泛化。

## 4 比较方法和实际字节预算

### 4.1 必要方法

| 方法 | 本轮用途 | 是否要求性能测量 |
|---|---|---|
| 官方低精度固定 codec | 主比较对象 | 否 |
| 官方高精度固定 codec | 判断问题是否仅是正常精度效应 | 否 |
| 分块均匀随机量化，FP32 scale，BF16 解码输出 | 简单且可审计的误差与字节参照 | 否 |
| BF16 identity | 输入基准和未压缩包字节参照 | 否 |

不默认加入本地 G1 codec。只有需要区分“官方路径也有问题”与“本地改写才有问题”时，才对一条线索附加本地对照，且名称保持 local_repaired_codec。

### 4.2 uniform 的明确契约

uniform block size 仅取 g∈{16,128}，码宽 q 是实际打包宽度。令 M=2^(q−1)−1，整数码范围为 [−M,M]，每个码以 q 位紧凑打包；一个剩余码值保留不用。scale 是每块一个 FP32 值，零块固定 scale=0、整数码=0。

非零块以 max_abs/M 得到 FP32 scale；以 FP64 检查 M×scale 是否覆盖块最大绝对值，若未覆盖，则向正方向取下一个 FP32 值，直至覆盖。归一化、floor 和舍入概率用 FP32；以独立 U∈[0,1) 随机舍入到相邻整数并限界。解码先以 FP32 相乘，再按 round-to-nearest-even 转 BF16。记录有限精度细节，不把理想实数无偏性直接当成实现性质。

编写简洁 CPU/PyTorch 参照即可，不优化性能。必须生成并解包真实紧凑字节，保存独立解码检查；不能拿 int64 张量存储大小当 q 位包，也不能仅用 q×D/8 公式充当实测字节。

### 4.3 用实际包确定有限配置

先在 D0 确定官方低/高精度组件对 D=818048 的实际包预算 C_low/C_high。参数选择只依据包大小，不查看误差结果。uniform 在给定 g 下的基础包大小为 ceil(P×q/8)+4×P/g，P=g×ceil(D/g)；有额外必需头部或对齐时再计入。

- 低精度主比较：对每个 g，在整数 q∈[2,10] 中选择实际总字节不超过 C_low 的最大 q，记为 q_minus；仅当 q_minus<10 时另取 q_plus=q_minus+1，作为预算上邻。q_minus=10 时没有本轮允许的上邻。合计最多 4 个 uniform 配置。
- 高精度对照：对每个 g，只选不超过 C_high 的最大 q，合计最多 2 个配置。与已有配置重复时去重。
- 若没有下邻、没有合法上邻，或包大小依赖内容，应记录实际情况。对变长包使用 D0 已明确的上界作选择，并逐输入报告真实字节；无法形成一致预算关系时只画实际点，不扩搜索。

因此最多 2 个官方配置、6 个 uniform 配置和 1 个 BF16 参照。高精度档缺失时保留低精度有效结果，标为覆盖不完整，不另找第三个外部方法。

每个点都报告 payload、scale、必需 header/alignment 和总字节。padding 已包含在这些字节中，不重复加算。码本、种子建立、必须的协调信息和持久状态另外列出；若是逐输入必需的通信，应计入本次包预算，不能称为免费。

名义 b4/b8 不表示实际 4/8 位。现有 G1 的 5/9 位结论也不能移植到官方实现。预算不相同就展示误差—实际字节点和 Pareto 关系：只有某方法同时不多用字节、误差不更差时，才能说在所测指标上支配另一个点。预算上邻只说明多付字节的效果，不能算等预算胜出；不额外填充无效字节来制造相等预算。

## 5 测量内容和数学口径

### 5.1 局部量化误差

对每个快照、worker、方法和随机重复，保存 y_r=decode(encode(x_r))，仅在逻辑部分以 FP64 计算 e_r=y_r−x_r：SSE、MSE=SSE/D、输入能量、SSE/输入能量、最大绝对误差和非有限值数量。分母为零时写 null 并说明原因；失败输出不能进入有效平均值。

允许记录解码到 BF16 前后的误差分项，前提是官方接口原本能够提供，不为此重写内核。所有正式比较使用同一最终输出精度；若官方组件无法提供该精度，则在 D0 明确转换位置、成本和组件范围，不忽略差别。

### 5.2 一次编码后的聚合诊断

复用同一重复内四个 worker 已解码的结果，不追加 codec 调用。以 FP64 定义：

- t=Σ_r x_r，a=Σ_r y_r，E_sum=||a−t||²。
- source_energy=Σ_r ||x_r||²，target_energy=||t||²。
- source_normalized_error=E_sum/source_energy。
- target_relative_error=E_sum/target_energy。
- cancellation_ratio=target_energy/source_energy。
- local_error_sum=Σ_r ||e_r||²，cross_term=E_sum−local_error_sum。

另外保存 aggregate MSE=E_sum/D 和最大绝对误差。零分母为 null；cancellation_ratio<1e−6 时附 near_cancellation 标记，并同时展示绝对误差及两种归一化结果，不能只凭很大的 target_relative_error 断言噪声放大。cross_term 是本次实现和随机重复的诊断量，单次非零不等于已经发现系统性跨 worker 相关。

这个操作命名为 one_shot_codec_sum。**它是每个 worker 独立压缩一次后求和，既不是官方 AllReduce，也不是 G2a 的多跳 ring。** BF16 identity 在这个 FP64 求和参照下量化误差应为零；不把它解释成 BF16 网络归约没有加法舍入。

本轮只记录 Σ_r packet_bytes，字段名为 one_shot_packet_bytes_sum；它不是网络 total wire bytes。没有实际执行 ReduceScatter/AllGather，不乘套 ring 系数，也不报告 collective 加速。

### 5.3 汇总与可选计时

先对每份固定输入汇总 8 次随机重复的均值、标准差、最小和最大值，再逐快照展示。总量由 SSE 和能量相加后计算，不能把层级或 worker 的相对误差简单平均。保留每次原始值，不挑最好种子，不把总体平均隐藏的回退删掉。

默认不做性能竞赛。若已有两条经过验证、实现成熟度相当的 GPU 路径，可附少量局部计时：只选低精度主比较的一对配置、一个真实输入长度，三次 session；明确 RNG、打包、尺度、输出转换、分配和初始化哪些计入。测量方式复用 G1 的预热和配对框架，计时与正确性审计分开。Python uniform 对官方 CUDA 不具备算法性能可比性；不能为了补齐这张图新增 CUDA 工程。

正式结果最多两张主要图：实际字节—局部误差、实际字节—one-shot 聚合误差，按快照区分并展示随机离散程度。性能未测是符合范围的结果。

## 6 只追查一条有价值的线索

D1 比较完成后，先检查输入、dtype、舍入、真实字节、随机状态、输出精度、尺度粒度和独立解码契约。发现自写 wrapper 或 uniform 错误时先修正，记录变更并重跑受影响条目；这种错误不算官方方法的问题。

候选线索须同时具有：

1. 真实输入证据：至少两个开发快照方向一致；若只出现在一个快照，则有可重复触发条件和可估计的出现范围，先标待确认。
2. 实际意义：结合输入和聚合能量、涉及输入比例、潜在用途或局部资源成本说明为何值得处理。不能仅凭近零参照引起的巨大相对误差升级，也不能仅因原始 MSE 数字很小否决线索；梯度整体缩放会改变绝对误差。
3. 可定位性：指出具体算术、尺度、存储或接口步骤，而不只是“低比特误差较大”。
4. 可行动性：有一项可能改变结果的具体干预，并列出它需要的统计、元数据、计算及协议成本；本轮不要求实现新算法。
5. 可信范围：问题存在于所声明的官方组件，或本身是重要的接口/适用边界问题，不只是本地改写产生的现象。

最多对一条线索做两项单因素对照，优先使用已有参数或参考运算，在原开发输入和相同随机重复上执行。例如把可疑尺度舍入替换为高精度参考，以定位误差来源；该输出只能标 oracle_diagnostic，必须列出额外精度或存储成本，不能当成免费可部署方法。若需要大量重写官方算术才能做对照，就提交未解决项。

从至少两个可能线索中挑选时，报告选择依据和其余线索，不能只留有利个案。定位后查最接近的一组原始论文及官方实现说明，回答：这是作者已说明的取舍、已修复缺陷，还是仍值得独立验证的问题？已有论文不等于结论不可修正，但必须解释新增证据会改变什么认识或设计。

## 7 继续或停止的决定

| 最终判断 | 条件 | 下一步 |
|---|---|---|
| baseline_blocked | 官方组件未通过 D0 | 交付阻碍，不继续模拟性能或换成本地官方冒名基线 |
| no_actionable_signal | 有效比较中未发现具体问题，或只是已知正常取舍 | 本轮结束，不追加新数据来寻找正结果 |
| inconclusive | 方向不稳定、比较条件不齐或无法定位 | 明确缺口和修复成本；不自动扩大实验 |
| candidate_for_confirmation | 正确性和字节通过，有一条有意义且可定位的线索，已核对近邻工作 | 提出 D2 最小确认方案，交回评审 |

不以“uniform 在某个点赢了”自动升级。固定组件比较也不能据此否定 DynamiQ 的动态策略、完整协议或训练效果。没有发现线索只支持“这次有限诊断没有找到可推进对象”，不支持“我们不可能做出独立贡献”。

D2 方案仅在最后一种情况下写入报告：预先冻结一个主张、一个主要指标、比较方法和判定规则；优先一条新的小模型训练随机种子/独立轨迹、最多两个预先指定的快照，各四个 worker。若使用现有未接触数据，先核查历史使用记录。新舍入 seed 或同一快照切片不能充当独立训练输入。

**本轮到报告交付结束，不采集 D2 数据、不执行 D2，也不启动完整训练对比。** 下一轮确认支持后，才讨论新方法实现、必要理论和更强基线。异常、失败案例、已知方案的适用边界或有效改进均可能成为贡献来源，但都要靠独立证据和与现有工作的具体区别成立。
